## OneRec-Think：从文本推理到物品生成

**核实版本：v2。** [首页条目](../README.md#paper-onerec-think)

- **推理位置：** 先生成文本轨迹，再据此生成物品 token。训练依次进行物品语义对齐、轨迹监督与 GRPO 奖励优化。[§3–4](https://arxiv.org/html/2510.11639v2#S4)
- **效果证据：** Beauty 数据集的 Table 2 比较 Base、Base+IA 和 Base+IA+R；加入推理后，Recall@5 从 0.0532 到 0.0563。这里是训练配置的组件对照，不能单独证明增加预测时 token 是收益来源。[§5.3](https://arxiv.org/html/2510.11639v2#S5.SS3)
- **成本处理：** Think-Ahead 将推理与初始物品 token 放到离线阶段，在线模型补全剩余 token；两段计算应分别记录。[§4.4](https://arxiv.org/html/2510.11639v2#S4.SS4)
- **资源状态：** [官方仓库](https://github.com/wangshy31/OneRec-Think) 可见训练、测试和数据目录；本仓库未运行，完整权重与工业数据可用性未核实。
- **阅读判断：** 适合入门“语义对齐 → 推理 → 物品生成”。进一步需要预算匹配实验来区分各阶段贡献。

<a id="gr2"></a>
## GR2：推理如何服务重排目标

**核实版本：v6。** [首页条目](../README.md#paper-gr2)

- **推理位置：** 对候选进行比较后输出重排结果；先学习教师轨迹，再用 DAPO 优化。条件格式奖励用于缓解保留原排序获取奖励的捷径。[§4.2–4.3](https://arxiv.org/html/2602.07774v6#S4.SS3)
- **效果证据：** §5.4 在 Beauty、Sports 上比较多种轨迹与 SFT/RL 组合，候选列表大小为 10。部分配置优于初排，部分退化；不能概括为任意推理配置都有效。[§5.4，Table 5–6](https://arxiv.org/html/2602.07774v6#S5.SS4)
- **成本记录：** 存在教师数据生成和预测时轨迹生成开销；本轮未核实可直接比较的端到端延迟。
- **资源状态：** 官方代码、权重与完整复现材料未核实。
- **阅读判断：** 推荐质量与轨迹流畅性需要分别评估；此处的候选重排指标不应与全库检索直接排名。

<a id="onereason"></a>
## OneReason：分开评估推理训练与推理预测

**核实版本：v1；arXiv 标注 Work in progress。** [首页条目](../README.md#paper-onereason)

- **推理位置：** 将物品语义感知与三层兴趣推理结合，经 SFT 和分阶段 RL 训练。[摘要](https://arxiv.org/abs/2606.06260)
- **效果证据：** §6.4 比较 thinking/non-thinking 及多种训练策略，不同领域和指标的结果有差异。§8.2 用相同 0.25B 训练 token 比较不同 CoT 监督混合，并统一用 non-thinking 预测：部分领域改善，Cross-Ad 是例外。[§6.4](https://arxiv.org/html/2606.06260v1#S6.SS4)、[§8.2，Table 17](https://arxiv.org/html/2606.06260v1#S8.SS2)
- **成本记录：** 上述预算对齐的是训练 token，不是预测时计算；本轮未核实统一的端到端延迟比较。
- **资源状态：** 官方代码与权重未核实。
- **阅读判断：** 推理监督可能改善不输出推理的模型。评估时应将“学习推理”和“预测时展示推理”分开。

<a id="ttr"></a>
## 多模态对话检索中的 TTR

**核实版本：v1。** [首页条目](../README.md#paper-ttr)

- **推理位置：** 从对话理解意图，生成商品语义 ID，再由测试时评价器估计候选与意图的匹配程度并重排；核心是候选验证。[§3](https://arxiv.org/html/2508.18132v1#S3)
- **效果证据：** Table 3 在三个对话数据集上给出逐轮 MRR 的有无 TTR 对照，作者报告加入重排后提升。该设置是多模态对话商品检索。[§5](https://arxiv.org/html/2508.18132v1#S5)
- **成本记录：** 作者将新增评价计算写为 O(A×B)，A 为候选商品数，B 为每商品的 SID 数；可并行不代表没有额外计算。具体硬件下的统一延迟对照本轮未核实。[§3.3](https://arxiv.org/html/2508.18132v1#S3.SS3)
- **资源状态：** 论文描述 MFR、MMD 的整理版本及模拟对话数据；代码和这些处理版本的下载入口未核实。
- **阅读判断：** 适合与文本 CoT 和潜在迭代比较，但不要将三种机制视作同一类成本。

## AgentDR：关系推理与推荐工具协作

**核实版本：v3。** [首页条目](../README.md#paper-agentdr)

- **推理位置：** 推断历史物品的替代与互补关系，选择推荐工具，并据此重排候选。[§3.3–3.6](https://arxiv.org/html/2510.05598v3#S3.SS3)
- **效果证据：** §4.5–4.6 比较聚合方式、工具比较和关系重排。工具比较在 Instacart 有退化，不应写成每个模块始终有益。[§4.6](https://arxiv.org/html/2510.05598v3#S4.SS6)
- **成本记录：** 作者给出总调用数 6n+3nt（n 为用户数，t 为优化轮数）；少于 1 秒的列表生成结果是在记忆更新完成后测得，不能代替整条链路耗时。实验使用 Phi-4、vLLM 和 8 张 32GB V100。[附录 A.1–A.2](https://arxiv.org/html/2510.05598v3#A1.SS2)
- **资源状态：** 官方代码与完整复现入口未核实。
- **阅读判断：** 适合理解工具协作与关系推理；组件消融不等于推理文本忠实性验证。
